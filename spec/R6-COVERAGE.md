# MIPS32 Release 6 instruction coverage (Wave R6-7 audit)

Source: every instruction page of MD00086 Vol II-A Rev 6.06 (`python3 manuals/mipsdoc.py list`: 263 rows, duplicate titles DIV and MUL counted per page). Profile: CLAUDE.md "Target profile" (R6, LE, 64-bit FPU, NAN2008, Fixed Mapping MMU, no optional modules). Model: code branch `dev/r6` at 63e01a2 (end of wave R6-7); 203 `Instruction` constructors. Checked by `tools/compliance.py check` (every list entry once, class counts as stated).

## Counts

| class | pages |
|---|---:|
| (a) IMPLEMENTED | 137 |
| (b) REMOVED IN R6 | 77 |

GAPs found by this audit and closed in R6-7: **DVP** (p.172-173) and **EVP** (p.181-182) — the model raised Reserved Instruction; the pages require a NOP when `Config5.VP = 0` (the profile). They are now constructors `dvp`/`evp` (row class (a)). Reproducer before the fix: `tests/oracle/r6gap_dvp_evp.asm` (model RI x4, QEMU no-op).

How verified: "decode probe" = `decode` evaluated on the word in a scratch Lean file run with `lake env lean` (results: DECODES <ctor> / none, and for none the encoding space that decides the exception in `Step.execute`: COP0 -> CpU CE=0 outside Kernel Mode else RI; COP1 -> CpU CE=1 if CU1=0 else RI; COP2 -> CpU CE=2; else RI). Words from `llvm-mc-21 -show-encoding` (`-triple=mipsel -mcpu=mips32r2` for pre-R6 forms, `-triple=mips64el -mcpu=mips64r2` for PS/DDIV, `-mcpu=mips32r6 -mattr=+eva,+crc,+ginv,+virt` for modules) or built from the page diagram. The decode results for the module/TLB/EJTAG words are also kept as `example`s in `Semantics/Tests/InstructionTests.lean`.

## Assembler idioms and aliases the Release 6 pages document

All citations MD00086 Vol II-A Rev 6.06 (`python3 manuals/mipsdoc.py grep "[Ii]diom|alias" -d v2`). "llvm" = `llvm-mc-21 -triple=mipsel -mcpu=mips32r6 -show-encoding` (run in this audit).

| form | page text | our assembler | llvm-mc-21 r6 | checked by |
|---|---|---|---|---|
| `B offset` | B p.49 "interpreted by the hardware as BEQ r0, r0, offset"; BEQ p.72 | `beq $0,$0,off` | accepts (`b 8` = 0x10000002) | encodings.list, AsmTests |
| `BAL offset` | BAL p.50 (Release 6: REGIMM BAL, the rs = 0 case of the removed BGEZAL; BGEZAL p.76) | `bal` constructor | accepts (0x04110002) | encodings.list |
| `NAL` | NAL p.306 | `nal` constructor | accepts | encodings.list |
| `NOP` | NOP p.312; SLL p.376 | `sll $0,$0,0` | accepts | encodings.list |
| `SSNOP` | SSNOP p.387 "Assemblers targeting specifically Release 6 should reject the SSNOP instruction with an error"; SLL p.376 | **rejected** since R6-7 (error cites p.387); the word 0x00000040 still decodes as `sll` (a no-op) | accepts (0x00000040) | AsmTests #guards (error, message, decode); `ssnop` line removed from encodings.list |
| `EHB` | EHB p.175 | `sll $0,$0,3` | accepts (0x000000c0) | encodings.list, AsmTests |
| `JR rs` | JR p.206-207 "JALR with ... rd set to 0"; Table A.3 note 3 p.452 "Assemblers should produce the new instruction" | `jalr $0, rs` | accepts (0x01000009) | encodings.list, AsmTests |
